# CA-PC: Observation-Aware Canonical-Anchored Prototype Correction

Code and experiment records for **CA-PC**, a training-free, annotation-free prototype correction framework for cross-domain open-vocabulary detection in remote sensing.

> Manuscript: *Observation-Aware Canonical-Anchored Prototype Correction for Cross-Domain Open-Vocabulary Detection in Remote Sensing*, under review at **IEEE Transactions on Geoscience and Remote Sensing (TGRS)**, 2026.

This repository is **private** while the manuscript is under review. It will be made public upon acceptance, in line with the data-availability statement of the paper.

---

## What is included

| Path | Contents |
|---|---|
| `code/` | 724 Python scripts: detector evaluation, prototype construction, closed-loop calibration, decomposition probes, ablation and cost profiling, plus all figure-generation scripts. |
| `data/results/` | 503 JSON result files produced by the scripts (per-table numbers, per-class AP, bootstrap records, cost profiles). |
| `data/cache/confirm_split_cache/` | Per-box detection cache for the DIOR→COCO six-class protocol (GroundingDINO-tiny): `box`, detector score `gd`, ground-truth `gt`, CLIP crop features `F`, source/negative prototypes, and the canonical shift `Delta`, for all six target classes. This is the cache behind the forward closed-loop tables and the R2#4 extra-metric experiment. |
| `docs/` | Internal notes: review triage and the R2#3/R2#4 experiment report. |

**Not included** (too large for a Git repository, or third-party weights): model checkpoints (`*.pt`, `*.safetensors`), video/animation assets, frame dumps, and the large probe caches under `probe_*_cache/`. Those caches are regenerated by the scripts in `code/` from the public datasets.

## Reproducing the reviewer-requested experiments

### R2#3 — cost comparison against baselines

No model run is needed; the numbers are measured records:

```bash
python -c "import json;print(json.load(open('data/results/complexity_profile.json')))"
python -c "import json;print(json.load(open('data/results/tge_cost_analysis.json')))"
```

Key values: base GroundingDINO-tiny detection 734.2 ms/image, CLIP encoding 16.9 ms/box; CA-PC adds **0.079 ms/image** (50 proposals), **0.0016 ms/box**, **+8.35 ms** one-time anchor encoding, **0 trainable parameters**, **≈0 extra GPU memory**.

### R2#4 — precision / recall / F1 / box-IoU with multi-split CIs

`code/r2_extra_metrics_offline.py` reads the cache only (no detector re-run):

```bash
python code/r2_extra_metrics_offline.py
```

Protocol:
- scoring `s = sqrt(q * clip(F·W))` with `W = unit(P_src + 2.0*Delta) - 0.5*P_neg` (paper main configuration, β=2.0, λ=0.5);
- per-image greedy matching at IoU ≥ 0.5, IoU denominator `1e-8` — bit-identical to `unified_eval.py::compute_ap50_img`;
- first 10 images per class excluded as calibration; proposals pre-filtered at 0.03;
- precision/recall/F1 are read at the **max-F1 operating point** of the pooled PR curve (threshold-free); box-IoU is the mean IoU of matched TPs at that point;
- significance: paired image-level bootstrap (B=1000, same resample indices for base and corrected) and 5 random global COCO-image-id splits.

Reference output (`data/results/r2_extra_metrics_20261118.json`):

| Metric | base | CA-PC | Δ | 95% CI (paired bootstrap) |
|---|---|---|---|---|
| F1 | 0.2327 | 0.2989 | **+0.0663** | [+0.0546, +0.0788], P(Δ≤0)=0 |
| Precision | 0.2133 | 0.2615 | +0.0482 | — |
| Recall | 0.2560 | 0.3487 | +0.0927 | — |
| box-IoU | 0.8875 | 0.8763 | −0.0073 | [−0.0150, +0.0007], not significant |

Five random splits give ΔF1 = +0.0647 ± 0.0064 (5/5 positive) and ΔAP50 = +0.0568 ± 0.0051.

The slight box-IoU decrease is expected: CA-PC re-scores cached proposals and never moves a box, so admitting more low-confidence proposals lowers the mean IoU of matched TPs at the F1-optimal point. It is neither a gain nor a defect of the correction.

## Metric conventions

- **AP50**: eleven-point interpolated average precision at IoU 0.50, per-image greedy matching (denominator `1e-8`), dataset-level pooling. `unified_eval.py` is the reference implementation.
- **mAP@[0.50:0.95]** and **AP75**: COCO-style, 101-point interpolation, computed by `unified_eval.py::compute_ap_coco`.
- **Base scorer**: `s_base = sqrt(q * max(0, F·W_base))` with `W_base = unit(P_src) − λ P_neg`, i.e. the uncorrected prototype, not the raw detector confidence. Condition-axis probes use the raw detector confidence by design; the two baselines are never mixed inside one table.
- **Bootstrap**: paired, image-level resampling; B=600 for the main cross-detector table, B=1000 (seed 20261021) for the supplementary protocol.

## Note on code provenance

The scripts are the actual research code, kept in their working form rather than refactored into a package. Some are one-off probes or figure scripts and contain hard-coded local paths and Chinese comments. `unified_eval.py` and `confirm_devtest_global_split.py` are the two entry points that define the evaluation protocol used by every table in the paper.
